# 记忆服务

`intake.rs` 负责收件、净化来源查询、分页和加密图片附件读取；`source_edit.rs` 负责提交者修订原文，重新隔离秘密、加密并撤销旧任务租约。来源 ID 不变，修订使用乐观版本校验，未变化的凭据保留原授权。

`nodes.rs` 管理知识条目和来源删除；`queue.rs` 负责后台整理。来源编辑与删除先锁任务再修改来源，后台旧租约不能覆盖新状态。

纯文本聊天中的明确问候和查找在收件事务中标记为 `recorded`，不创建整理任务或提及关系。原文仍加密留存，重复提交仍按请求 ID 返回相同来源；不能等到前台路由完成后才撤销后台任务。

`isolate.rs` 隔离已知凭据，并对不完整赋值、多行秘密和未标注的不透明文本保密暂存；普通 JSON 字符串保留，重复值及字段名统一净化。`clarification.rs` 只接受同一空间、提交者、聊天引用中的明确整段秘密说明，保存来源版本与解释记录后才重新排入整理。

`source_dedup.rs` 在同一空间、同一提交者范围内串行检查收件和编辑。随心记、导入及编辑遇到已有原文时拒绝写入，忽略首尾空白和 CRLF/LF 差异，保留大小写及正文内部空白。净化模板仅筛选候选，最终通过宿主解密比较，不保存原文散列。请求重试仍先走原有幂等检查；聊天轮次和澄清来源保留独立记录。

`ssh.rs` 维护 SSH 主机元数据并转发设备动作：主机记录只保存 alias、主机、用户、端口、身份文件名和配对设备标识，不保存私钥或密码；调用经宿主 Unix socket 的 `POST /workers` 发往配对设备，设备端只接受固定动作白名单。删除和写入只在设备回报 `state=complete` 后更新状态或删除记录，失败保留记录并写入 `last_error`。

`GET /sources?distinct=true` 对过滤后的普通文本来源先去重再计数、分页，同一提交者保留最新版本的卡片。历史数据及证据关联不删除，默认来源管理查询仍返回原始记录；保密暂存和带秘密字段的历史来源不按占位符合并，避免隐藏不同秘密。
